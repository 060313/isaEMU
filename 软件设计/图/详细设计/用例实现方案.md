## 二、分析类到设计类的转换方式

技能规定三种转换方式：

- **方式一**——一个分析类的一项职责，由一个设计元素的**单个方法**完整实现；
- **方式二**——一个分析类的一项职责，由一个设计元素的**多个方法**实现；
- **方式三**——一个分析类的一项职责，由**多个设计元素协作**完成。

| 分析类 | 职责 | 设计元素 | 方式 | 说明 |
| --- | --- | --- | --- | --- |
| `SessionController` | 凭据校验、开会话、建隔离工作区 | `SessionService` | 方式二 | `login()` / `createSession()` / `createWorkspace()` 三个方法 |
| `SessionController` | 列出用户与资源占用 | `SessionService` + `WorkspaceService` | **方式三** | 账号数据与会话数据归属不同服务 |
| `IsaController` | 校验 ISA 描述 | `IsaValidator` | 方式一 | `validate()` 单方法完整实现 |
| `IsaController` | 装载并切换当前 ISA | `IsaRegistry` + `IsaSpec` + `DecodeTable` | **方式三** | `install()` 编排 parse → validate → build 三步 |
| `LoadController` | 汇编转码 | `ToolchainAdapter` | 方式一 | `assemble()` 单方法 |
| `LoadController` | 按基址载入并初始化 | `LoadService` + `ProgramImage` + `EmulatorCore` | **方式三** | 载入、初始化状态分属不同构件 |
| `DebugController` | 单步/运行/暂停/复位 | `DebugService` | 方式二 | 四个方法对应四种运行控制 |
| `DebugController` | 断点登记与命中检查 | `DebugService` + `BreakpointTable` | **方式三** | 流程在服务、数据在断点表 |
| `TestController` | 批量执行、判定、汇总 | `TestService` + `Persistence` + `CompareEngine` | **方式三** | 流程、持久化、比对三方协作 |
| `DiffController` | 驱动双方执行并比对 | `DiffService` + `EmulatorCore` + `RefSimAdapter` + `CompareEngine` | **方式三** | 系统内最长的跨构件协作链 |
| `ApiController` | 解析、鉴权、限额、分发、封装 | `HttpGateway` + `AuthFilter` + `QuotaGuard` | **方式三** | 按三个变更原因拆分 |
| `ApiEndpoint` | 请求接收与响应回送 | `HttpGateway` | 方式一 | `handle()` 单方法 |
| `ApiEndpoint` | 状态增量推送 | `StatusChannel` | 方式一 | `push()` 单方法 |
| `EmulatorCore` | 取指—译码—执行—写回 | `EmulatorCore` + `ProgramImage` + `DecodeTable` + `ArchState` + `Trace` | **方式三** | 管道四级由不同构件承担，内核仅编排 |
| `EmulatorCore` | 终止与异常判定 | `TrapUnit` | 方式一 | `check()` 单方法 |
| 各 `*View` | 界面呈现 | 对应前端视图类 | 方式二 | 渲染与交互各为独立方法 |

**统计**：方式一 6 项、方式二 4 项、方式三 8 项。**方式三集中在"跨构件协作"处**——这恰好是体系结构第 5 章把 7 个子系统拆开的直接后果，不是设计阶段的额外复杂化。

## 三、逐用例实现要点

| 用例 | 主要设计类 | 实现要点 | 承载需求 |
| --- | --- | --- | --- |
| **UC-01 注册与登录**（UD-01） | `SessionView` `SessionService` `Persistence` `Session` `WorkspaceService` | 凭据校验经 `Persistence::findUser()`；会话与隔离工作区**分别创建**，工作区的创建委托给 `WorkspaceService` 而非 `SessionService` 自行持久化 | FR-9.1、FR-9.4、FR-9.5 |
| **UC-02 ISA 装载**（UD-02） | `IsaView` `IsaRegistry` `IsaSpec` `IsaValidator` `DecodeTable` | `IsaRegistry::install()` 编排三步：`parse()` → `validate()` → `build()`；**校验不通过即中断装载**，返回问题清单而不落库 | FR-1.1~FR-1.3 |
| **UC-03 程序装载**（UD-03） | `LoadView` `LoadService` `ToolchainAdapter` `ProgramImage` `EmulatorCore` | 汇编源分支经 `ToolchainAdapter::assemble()`；机器码分支**跳过适配器**；载入后由 `EmulatorCore::init()` 复位 PC / SP | FR-2.1~FR-2.4 |
| **UC-04 单步与连续执行**（UD-04） | `DebugView` `DebugService` `EmulatorCore` `ProgramImage` `DecodeTable` `ArchState` `Trace` `TrapUnit` | `step()` 内部四级管道；每步结束必查 `TrapUnit`（终止 / 异常）；`run(n)` 为 `step()` 的循环封装，**轨迹可关断以换吞吐**（NFR-Q1） | FR-3.1~FR-3.5、FR-4.1 |
| **UC-05 断点管理**（UD-05） | `DebugView` `DebugService` `BreakpointTable` `EmulatorCore` | 断点数据由 `DebugService` 持有（其生命周期与调试会话绑定）；命中检查在**每条指令执行前**由内核触发 | FR-4.2 |
| **UC-06 状态与轨迹查看**（UD-06） | `DebugView` `DebugService` `ArchState` `Trace` `StateStore` | 状态读取为**只读**操作（`snapshot()` 返回值对象）；四类视图由 `StateStore` 统一驱动刷新 | FR-5.1~FR-5.4、NFR-Q3 |
| **UC-07 回退执行历史**（UD-07） | `DebugView` `DebugService` `Trace` `ArchState` `StateStore` | 回退 = `Trace::snapshotAt(no)` + `ArchState::restore()`；**要求 Trace 记录完整快照或可逆增量**，这是 FR-4.4 的实现前提 | FR-4.4 |

| **UC-09 查看测试报告**（UD-09） | `TestView` `TestService` `Persistence` `TestReport` | 报告按需从持久化加载；失败现场 = 快照 + 首个差异点，二者**分两次取**以减小首屏开销 | FR-6.3 |
| **UC-10 一致性对拍**（UD-10） | `DiffView` `DiffService` `EmulatorCore` `Trace` `RefSimAdapter` `ProcessRunner` `CompareEngine` `DiffScope` `Divergence` | 双方并行执行；`RefSimAdapter` 经 `ProcessRunner` 启 Spike 并解析提交日志；**首个分歧即停**并落 `Divergence`；基准不可用时退化为快照断言 | FR-7.1~FR-7.3、FR-7.5 |
| **UC-11 分歧归因**（UD-11） | `DiffView` `DiffService` `Divergence` `Persistence` | 查询与标注两段；标注结果经 `Persistence::saveDivergence()` 落库，供跨会话复用 | FR-7.4 |
| **UC-12 工作区保存/加载**（UD-12） | `AdminViews` `WorkspaceService` `Persistence` `ProgramImage` `TestSuite` | 保存与加载**共用一张顺序图**；加载时需恢复程序映像与用例集两部分 | FR-9.3 |

## 四、三处需在设计中特别留意的实现约束

1. **`RunContext` 是 NFR-Q2 的唯一落点**。批量测试中"每用例独立上下文"这句话，落到代码上就是 `TestService` 为每个用例 `new RunContext(core, archState, trace)`。若图省事共享一个 `EmulatorCore`，单个用例越界或死循环会污染后续用例，可靠性需求即失效。
2. **`Trace` 的回退能力决定 `ArchState` 的存储策略**（UC-07）。两种实现：①每步存完整快照（内存开销 O(n·状态大小)，实现最简）；②存可逆增量（内存小，但要求每条指令的操作可逆，RV32I 中 `ecall` 等侧效指令需特判）。详细设计建议取 ①，并把"轨迹可关断"（NFR-Q1）作为性能开关。
3. **`RefSimAdapter` 的解析容错**（限制 L2）。Spike 的 `--log-commits` 输出格式非本项目可控，解析器必须容忍未知行、缺失字段与版本差异，并返回"部分可比"而非直接失败——否则 FR-7.5 的降级路径无从触发。
