## 1 软件背景介绍

指令集体系结构（Instruction Set Architecture，ISA）是软件与硬件之间的接口契约，它规定了处理器可见的指令编码、寄存器组织、内存寻址方式与特权行为。学习者、芯片设计者、指令集制定者与底层程序开发者都需要围绕这一契约开展工作，而他们共同依赖一个前提：**能够准确、便捷地观察到指令执行后体系结构状态发生了什么变化**。

近年来以 RISC-V 为代表的开放指令集迅速普及，围绕 ISA 的教学、验证与工具需求显著上升。目前满足这一需求的手段主要是三类：阅读规范手册与教材；搭建 RTL 级仿真环境（Verilator、VCS 等）；在真实硬件或 FPGA 上运行程序。这三类手段各有其成本——手册是静态的、无法执行；RTL 仿真启动与编译开销大、反馈周期长；真实硬件则难以逐指令观察与反复回退。

本项目拟开发一个**纯软件的 ISA 模拟系统**，以解释执行的方式重建指令级行为，并提供可视化、可调试、可批量验证、可与外部参考模拟器比对的能力。系统在执行内核与指令集定义之间保留抽象边界，首期完整实现 RISC-V RV32I 指令集，支持第二套指令集作为后续演进目标。系统以 Web 形式提供，支持云端访问与本地部署两种形态，并对外提供集成 API。

项目组由 5 名成员组成，开发工具为 Visual Studio Code，核心采用 C++ 实现，版本控制使用 Git 并托管于 Gitee 或 Github。

## 2 欲解决的问题

### 2.1 指令执行过程不可观察

ISA 规范以文字和公式描述指令语义，学习者只能在脑中"执行"这些语义。现有工具中，反汇编器只做静态翻译，调试器面向的是真实机器上的完整程序，都无法把"某一条指令执行前后，PC、GPR、内存、CSR 分别发生了什么"以即时、可视的方式呈现。

**影响**：学习曲线陡峭，概念性错误难以自查。

### 2.2 指令级功能验证成本高

芯片前端团队需要在 RTL 开发前或开发中对指令功能做冒烟级验证。当前做法依赖 EDA 工具链拉起完整仿真环境，编译与初始化开销远高于"跑几条指令看看结果"这一实际需求。

**影响**：验证迭代慢，简单问题被高成本流程掩盖；小规模验证需求无法被满足。

### 2.3 指令集规范本身的歧义难以发现

若只有一套实现，实现与规范之间的偏差无法被察觉——实现错了会被当成规范，规范本身自相矛盾之处也无人暴露。发现规范歧义的经典手段是让两套彼此独立的实现执行同一程序并比对结果，而业界缺少面向教学的、开箱即用的对拍工具。

**影响**：规范缺陷被推迟到流片或编译器适配阶段才暴露，修改代价高昂。

### 2.4 机器语言与汇编程序缺乏轻量调试环境

直接编写机器码或汇编的程序员，需要一个可以设置断点、单步执行、查看内存与寄存器，并能回退重放的环境。面向通用应用的高级语言调试器无法覆盖裸机场景。

**影响**：底层程序的调试效率低，错误定位依赖打印与猜测。

### 2.5 问题与相关方对应关系

| 问题             | 受影响相关方  |
| -------------- | ------- |
| 2.1 执行过程不可观察   | ISA 学习者 |
| 2.2 指令级功能验证成本高 | 工业芯片工程师 |
| 2.3 规范歧义难以发现   | ISA 工程师 |
| 2.4 裸机调试环境缺失   | 机器语言程序员 |

## 3 软件解决方案

### 3.1 总体思路

以纯软件的**解释执行内核**重现指令级行为，把"架构状态"变成可以被程序读取、展示、回放和比对的数据对象；在内核之上叠加**服务层（集成 API）**&#x4E0E;**Web 前端（可视化与交互）**，形成"内核可复用、界面可替换、能力可对外集成"的分层结构。指令的格式与语义以 **ISA 描述文件**形式提供，内核与指令集定义之间保持抽象边界；首期以 RISC-V RV32I 完整实现并验证该边界成立。

### 3.2 系统组成与职责划分

| 组成           | 由谁提供      | 承担职责                                                                           |
| ------------ | --------- | ------------------------------------------------------------------------------ |
| 模拟执行内核       | 本软件开发     | 取指—译码—执行—写回循环；维护 PC、GPR、内存、CSR 等架构状态；记录执行轨迹；识别非法与未定义编码；处理程序终止序列与运行期异常          |
| ISA 抽象层与描述装载 | 本软件开发     | 定义内核与 ISA 描述文件之间的抽象边界；装载并校验 ISA 描述文件；首期提供 RISC-V RV32I 描述                      |
| 服务端与集成 API   | 本软件开发     | 用户与会话管理；调试控制（单步、运行、暂停、断点）；测试用例编排与判定；对拍调度与差异汇总；对外提供 HTTP/WebSocket 接口           |
| Web 前端       | 本软件开发     | 寄存器、内存、反汇编、执行轨迹四类视图；单步与断点交互；测试报告与对拍差异报告呈现；示例程序与新手引导入口                          |
| 示例程序集        | 本软件开发     | 提供覆盖 RV32I 常用指令的演示程序与经典算法样例，支撑快速上手                                             |
| 外部汇编工具链      | 第三方提供（复用） | 将汇编源转换为机器码；工具链缺失时由用户自行提供机器码                                                    |
| 外部参考模拟器      | 第三方提供（复用） | 作为对拍基准执行同一程序并输出逐步架构状态。首期锁定 **Spike**，利用其 `--log-commits` 逐步提交日志；QEMU 等列为后续扩展目标 |
| 浏览器与宿主操作系统   | 环境提供      | 提供渲染容器与运行环境（云主机或本地主机）                                                          |
| Git 托管平台     | 环境提供      | 源代码、测试用例集与文档的版本管理与协作                                                           |

### 3.3 系统间的交互

- **前端 ↔ 服务端**：前端经 HTTP/WebSocket 调用服务端接口，发起装载、单步、运行、测试、对拍等请求，接收架构状态增量推送与结果数据。
- **服务端 ↔ 外部汇编工具链**：服务端以子进程方式调用工具链完成汇编，读取其产物与错误输出；工具链不可用时返回明确提示，不静默失败。
- **服务端 ↔ 外部参考模拟器**：服务端以子进程方式启动 Spike 执行程序，采集其逐步提交日志作为对照状态，供对拍使用。
- **服务端 ↔ 存储**：用户工作区（程序、用例集、配置）持久化到用户私有空间，不同用户之间互相隔离。
- **本地部署形态**：服务端与前端以容器或可执行文件形式部署在本地主机，功能与云端一致。

### 3.5 范围与边界

**本期功能范围（本系统负责）**：ISA 描述装载与校验（首期 RISC-V RV32I）、程序装载与运行配置、指令解释执行、程序终止与运行期异常处理、指令级单步与断点调试、寄存器与内存可视化、示例程序与新手引导、测试用例组织与批量验证、与 Spike 的一致性对拍、集成 API、多用户会话与隔离。

**本期不在范围内**：

| 排除项                | 说明                                 |
| ------------------ | ---------------------------------- |
| 周期精确的微架构建模         | 不建模流水线、缓存时序等微架构行为，仅做体系结构级（功能级）模拟   |
| 完整外设与中断建模          | 仅处理约定的终止序列与运行期异常，不建模完整的中断控制器与外设    |
| 操作系统级全系统仿真         | 不运行操作系统，面向裸机程序                     |
| 第二套指令集的完整实现        | 本期仅在架构上保留 ISA 抽象边界，不要求第二套 ISA 真正跑通 |
| QEMU 等其他外部参考模拟器的接入 | 本期对拍基准锁定 Spike，其余参考模拟器列为后续演进目标     |

**边界划分**：

| 由本软件实现                                                         | 由环境或第三方提供                                      |
| -------------------------------------------------------------- | ---------------------------------------------- |
| 指令语义解释、架构状态维护、调试控制、状态可视化、示例程序、测试编排与判定、对拍调度与差异归因、API 服务、用户与会话管理 | 浏览器渲染容器、宿主操作系统、外部汇编工具链、外部参考模拟器（Spike）、Git 托管服务 |
